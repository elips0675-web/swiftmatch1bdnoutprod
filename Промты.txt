# Промты для SwiftMatch (структура тестов и продакшн)

## 1. Функциональный аудит приложения
Проведи полный функциональный аудит веб-приложения SwiftMatch (дейтинг-приложение аналог Tinder).

Стек: React 18 + Vite + Tailwind (фронт), Express.js + MySQL (бэкенд), Socket.IO, Stripe, JWT.

### Что проверить:
1. АВТОРИЗАЦИЯ И РЕГИСТРАЦИЯ — регистрация, логин, logout, forgot password, verify email, dev-login
2. ПРОФИЛЬ ПОЛЬЗОВАТЕЛЯ — создание, редактирование, загрузка фото, удаление, настройки приватности
3. ЛАЙКИ И МЭТЧИ — свайп/лайк, мэтч, список мэтчей, геопоиск
4. ЧАТЫ — создание, отправка, история, typing indicator, read receipts, emoji-реакции, удаление, banned words
5. ПРЕМИУМ / МОНЕТИЗАЦИЯ — тарифы, Stripe Checkout, webhook, лимиты free vs premium
6. СОЦИАЛЬНЫЕ ФИЧИ — группы, конкурс, онлайн-статус
7. АДМИНКА — доступ, дашборд, пользователи, фича-флаги, рассылки, модерация, цены
8. ИНФРАСТРУКТУРА — /health, WebSocket heartbeat, Sentry, Swagger, CORS

Формат: для каждой функции статус (✅/❌/⚠️/❓), ошибка, файлы, приоритет (🔴/🟠/🟡/🟢).

## 8. Redis + Backup по этапам

### Этап 1: Redis
1. Подключить `getRedis`/`disconnectRedis` в `server/src/index.js`
2. Graceful connect при старте, disconnect на SIGTERM
3. Создать `server/src/cache.js` с:
   - `cacheRoute(ttl)` — кэширование по URL
   - `cacheRoutePerUser(ttl)` — кэширование по userId + URL
   - `setCached(key, data)` / `getCached(key)` — низкоуровневый API
   - `invalidate(pattern)` — сброс по паттерну (scanStream)
4. Кэшировать GET /api/profile/:id (60s), сброс на PUT profile
5. Кэшировать GET /api/matches (30s per-user), сброс на POST like→match
6. Добавить CACHE_TTL в server/.env.example

### Этап 2: MySQL Backup
1. Переписать `scripts/backup-mysql.ps1`:
   - auto-detect mysqldump (8 путей)
   - `cmd.exe /c` для вызова mysqldump (избежать проблем PowerShell с ANSI)
   - retention 7 дней
   - размер файла в выводе
2. Создать Task Scheduler: ежедневно 03:00

## 9. Production Readiness Checklist

### Security grep
```bash
grep -rE "dev-secret|localhost:300[0-9]|password.*=.*$|JWT_SECRET.*=.*key" \
  --include="*.env" --include="*.ts" --include="*.js" \
  --exclude-dir=node_modules --exclude-dir=dist
```

### Конфигурационная консистентность
- server/.env → PORT=3002
- vite.config.ts → proxy /api → localhost:3002
- .env → VITE_WS_URL, VITE_API_URL

### Платежный флоу (Stripe)
- STRIPE_SECRET_KEY, STRIPE_WEBHOOK_SECRET в server/.env
- mockFallback только при NODE_ENV !== 'production'
- Idempotency-Key на checkout.sessions.create
- express.raw({ type: 'application/json' }) перед express.json()

### Email / SMTP
- SMTP_HOST, SMTP_USER, SMTP_PASS, SMTP_FROM
- Не console.log как единственный транспорт

### WebSocket
- pingInterval 10000, pingTimeout 5000
- reconnect exponential backoff (max 30s)
- ack на сообщениях
- user:banned event разлогинивает

### File Upload
- limits: { fileSize: 5 * 1024 * 1024 }
- file.mimetype.startsWith('image/')
- uuid + оригинальное расширение

### Admin routes
- adminAuth middleware passive (next() на ошибке)
- req.user.role === 'admin' внутри хендлера
- Все PUT/POST/DELETE проверяют роль
- SQL в try/catch, пустой результат → [] или {}

### Sentry / Observability
- SENTRY_DSN в .env (frontend и backend)
- beforeSend фильтрует authorization, cookie, email, IP
- /health роут

### Тесты
- npm run test (frontend) — 0 failures
- cd server && npm run test — 0 failures
- npx playwright test — 0 failures
