Найденные и исправленные баги (по ходу E2E):

| Баг | Причина | Фикс |
|-----|---------|------|
| `PUT /api/profile/score` возвращал «Failed to update profile» | Роут был ПОСЛЕ `PUT /api/profile/:id` — тень маршрута (`:id` = "score") | Роут перенесён выше `:id` в `profile.js` |
| Настройки слали `/api/settings/privacy` и `/api/consent` БЕЗ токена → 401 | Отсутствовал `Authorization` в `settings.tsx` | Добавлены заголовки `Bearer getToken()` |
| `/profile` ловил 401 на `/api/photos/2` | `profile.tsx` слал запрос без токена | Добавлен `Authorization` |
| Каждый заход «выкидывал» в демо-юзера id 2 | `auth-context.tsx` при отсутствии Supabase всегда делал `dev-login`, перетирая сессию | Восстановление существующей сессии из JWT; dev-login только без токена. Тот же фикс в `admin-guard.tsx` |
| Сессия терялась при перезагрузке страницы | `token.ts` хранил токен только в sessionStorage | Fallback на `localStorage 'token'` в `getToken`, запись в оба хранилища в `setToken` |
| E2E падали на 429 «Too many requests» | Глобальный rate limiter 100 req/мин на IP (E2E пробивал) | Поднят до 600 req/мин (`index.js`) |
| E2E-флоу «не видел» аккаунт из storageState | Playwright не сохраняет sessionStorage; `global-setup.ts` писал только localStorage | Теперь пишет оба; конфиг `playwright.config.ts` → `workers: 1` (стабильность под лимитом) |
| Старый register E2E падал | Новый чекбокс согласия блокировал submit | Тест кликает `[data-testid="consent-checkbox"]` |

Прочее: `data-testid` для чипов (`icebreaker-chip`) и строк чатов (`chat-row-{id}`); старые тесты 4/8/12 раньше молча пропускали чат-шаги (не было `<a>`-ссылок — строки это `<div onClick>`).
