🔴 Критичные блокеры (держат релиз)
Нет staging-окружения. Все проверки — локально на Windows. Docker Compose «YAML валиден, но не поднимался». k6 100 VU не прогонялся. mysqld падал с RADAR_PRE_LEAK_64 под E2E-нагрузкой — неясно, как поведёт себя в проде.
Нет реальных API-ключей. Stripe LIVE, SMTP, Sentry DSN, S3, Twilio, OpenAI, FCM, RevenueCat — всё mock/fallback. Без этого нельзя:
принимать деньги (Stripe webhook → 502 в prod)
отправлять письма (лог «Would send»)
ловить ошибки в проде (Sentry молчит)
пушить на Android (FCM mock)
Нет домена + SSL + App Links. Android-релиз и Universal Links невозможны.
CSRF-защита неполная. SameSite=Lax не защищает от same-site атак (поддомены, open redirect). Double-submit token отложен «до выноса API на отдельный домен» — но это и есть стандартная prod-конфигурация.

🔍 Независимые находки (не упомянутые в других аудитах)
Слепая зона: Redis fallback под нагрузкой. REDIS_URL=invalid → кэш-промахи не должны DDOS'ить MySQL. В документации заявлен graceful fallback, но E2E-теста на это нет.
Слепая зона: Refresh race E2E. Два окна одного юзера с быстрым refresh в обоих — не покрыто. Unit-тест есть, E2E — нет.
Слепая зона: File upload security. 15MB отклоняется, .php.jpg, path traversal ../../etc/passwd — не покрыто тестами.
Слепая зона: Stripe webhook replay. Invalid signature → 400, idempotency-key без дублей — unit-тестов нет.
Слепая зона: Cross-browser. Playwright только на chromium. Firefox/WebKit не включены.
Грабли будущего: migrate.js не запускается из server/ (документировано в AGENTS.md), но CI-шаг на сервере делает cd — надо проверить, что в deploy.yml это явно прописано.
Дрейф версий: Node 25 в разработке vs Node 22-alpine в Docker — потенциальные расхождения в localStorage (Node 25 имеет глобальный localStorage, ломает jsdom).
🏁 Итоговый вердикт
Проект находится в состоянии «технически готов, операционно не разблокирован».
Это редкий случай, когда код, тесты, документация и архитектура опережают операционную готовность. Обычно бывает наоборот: «работает на коленке, но уже в проде». Здесь — наоборот: всё продумано, протестировано, задокументировано, но нет последнего шага — реального окружения с реальными ключами.
Главная рекомендация: прекратить писать новый продуктовый код. Все силы — на разблокировку прода:
staging VPS (1 день)
ключи в .env (1 день)
домен + SSL (1 день)
E2E на staging (2–3 дня)
Google Play релиз (1 неделя)
После этого — только reliability, monitoring и масштабирование. Проект имеет все шансы стать работающим SaaS-продуктом, а не очередным pet-project на GitHub.
