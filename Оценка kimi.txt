1	Push-уведомления для Android (FCM)	Без пушей мобильное приложение мёртвое — пользователи не узнают о мэтчах и сообщениях	Интегрировать @capacitor/push-notifications + Firebase Cloud Messaging. Заменить/дополнить текущие VAPID Web Push на FCM для нативного Android. Сейчас у вас только VAPID (веб-пуши), но в APK они не работают без Google Services.
2	Deep Links	Пуши открывают главную страницу вместо конкретного чата/профиля	Настроить Android App Links (assetlinks.json) + iOS Universal Links. В capacitor.config.ts добавить server.url для deep link handling.
3	Apple/Google IAP через RevenueCat	App Store и Google Play отклонят приложение без нативных встроенных покупок	Интегрировать purchases-capacitor (RevenueCat). Stripe оставить для веб-версии, но для мобильных сторов обязательны IAP. Это требование обоих магазинов для приложений с подписками.
4	SMS-верификация (Twilio/Vonage)	Дейтинг без верификации = 80% ботов и фейков	Докрутить существующий scaffold server/src/sms.js — добавить реальные API-ключи Twilio, rate-limit 3 SMS/час, интегрировать в флоу регистрации.
5	AI-модерация фото (AWS Rekognition)	NSFW-контент не отсекается автоматически = бан в сторах	Докрутить scaffold server/src/ai-moderation.js — подключить реальные ключи AWS Rekognition для nudity/violence detection при загрузке фото. Сейчас fallback на эвристику (regex) — недостаточно.

💡 Ключевой инсайт из рынка 2026
Согласно анализу рынка, 60–70% оттока пользователей из дейтинг-приложений происходит на этапе онбординга. Ваше текущее приложение уже имеет solid foundation (177 тестов, WebRTC, WebSocket, админка), но главный риск сейчас — не технический долг, а отсутствие мобильных пушей и нативных платежей. Без этих двух компонентов приложение в APK-билде фактически нежизнеспособно.
Приоритет: FCM → RevenueCat → Deep Links → SMS verify → CDN. Это 4–6 недель работы и разделит ваш продукт от «тестовой копии» до «приложения, которое можно выкладывать в сторы».
